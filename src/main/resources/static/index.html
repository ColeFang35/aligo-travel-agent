一、课题简介与学习方向

读完这一节，你就能建立对整套系统的心智模型：入口 → 意图 → 路由 → 执行 → 观测。
🧭

要解决什么问题？

一次“出差”包含机票、酒店、行程、报销审批等多个子任务，单智能体单 Prompt 无法承接。课题用多智能体 + 意图识别把一句话拆解并分别执行。

⚙️

哪些是框架能力（复用）？

Agent 循环、流式事件、Toolkit 工具注册、Middleware 动态 Prompt、Model 接入、Agent Handoffs —— 全部来自 AgentScope 2.0-Java，不自己再造。

🛠

哪些是本课题自研（亮点）？

意图识别引擎、快慢车道路由、卡片化响应、审批持久化(JSON)、以及火焰图/流程图/Prompt/记忆的本地调试助手。

🏫

对学生有什么用？

跟着「架构 → 流程 → 类图 → 亮点 → 运行」五步看，即可顺着一条请求的完整生命周期学到多智能体编程范式。

  alt 单意图 → 快车道
    O->>M: 直达 plan/approval_agent
  else 多意图 → 慢车道
    O->>M: main_plan 编排

    loop 每个子意图
      M->>SA: 子 Agent 接管 (Handoffs)

      SA-->>M: agent_end 卡片
    end
  end
  M-->>O: 汇总卡片
  O-->>W: 事件流 (think/text/card/done)
  W-->>U: 卡片化回复

五、项目亮点（答辩 / 报告要点）

本课题区别于“简单调用 API 的 Demo”的四个关键点。
框架内聚

1 · 只做编排，复用 AgentScope

Agent 循环、流式事件、Toolkit、Middleware、Model 全部用框架 API；课题只写业务编排与观测，符合“先查 API 再动手”。

意图引擎

2 · 快/慢车道路由

单意图直接走快车道；多意图混排走慢车道，按子意图拆分调度，并用 query 改写提升识别准确率（内置评测 v2=100%）。

上下文工程

3 · 动态 Prompt + 记忆 + RAG

Middleware 状态机按阶段动态拼 Prompt，会话记忆三表最小权限共享，KnowledgeBase 模拟 MaxKB 注入差旅政策。

可观测闭环

4 · 调试助手（火焰图/流程图）

全程 Trace，火焰图看耗时、流程图看拓扑、Prompt 快照可回放、内置意图评测形成“观测-评测”闭环。

六、学生学习路线（Recommended）

按顺序走完这 5 步，即可独立讲清并二次开发本项目。
  1. ① 跑起来 & 体验执行 mvn package 后启动，在 chat.html 里试用“规划行程、提申请、查记录、问报销标准”，感受卡片化多智能体协作。
  2. ② 读架构 & 类图对照本文第二、四节，找到 OrchestratorService / IntentClassifier / SubAgentFactory 三个入口类，读懂一次请求的流转。
  3. ③ 理解框架 vs 自研打开 pom.xml 与各 Service，标注哪些是 AgentScope API、哪些是自研逻辑，建立“复用优先”的意识。
  4. ④ 跟一次 Trace发送多意图话术后打开 debug.html，用火焰图与流程图回放同一条请求，理解 span 与工具耗时。
  5. ⑤ 动手改一处尝试加一个新工具（参考 ItineraryCardTool / ApprovalTool），或改阈值/槽位，重跑评测看准确率变化。
